Diagnostic System Guarantees & Stated Limitations

  • Non-Mutating Execution: All 6 diagnostic checks are strictly read-only. Diagnostics never write dummy files, execute database migrations, or alter production tables.
  • Schema Compatibility: Verifies the physical presence of required core tables; does not inspect Alembic revision table version heads.
  • Storage Paths: Non-mutating directory traversal verifies read/write permission bits without writing temporary probe files. Quota exhaustion cannot be detected prior to write.
  • Zero External Network: Diagnostics execute zero external HTTP or socket requests. Reference library integrity is verified strictly against local cryptographic digests.
  • Zero Approval Gates (Phase 8C Invariant): Newly ingested incidents immediately appear in the Incident Explorer without requiring reviewer keys, attestation, or editorial approval.
  • Epistemic Separation: Academic preprints and supplementary research signals are recorded as context references; only verified incident reporting feeds populate the primary incidents table.
  • Shared Concurrency: CLI, scheduled, and portal-triggered runs share the same advisory file lock (.data/ingestion.lock) with stale process recovery.
  • Durable Checkpoints: Successful collection records durable HTTP ETags and timestamps in .data/ingestion_checkpoints.json. Success timestamps are never updated on failed sources.
